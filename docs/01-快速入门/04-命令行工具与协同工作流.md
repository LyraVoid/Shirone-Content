# 命令行工具与协同工作流

Shirone 提供了一整套专为内容分离架构打造的 CLI 命令行工具。无论是在外部编辑器中日常写作、修改配置后的安全预检，还是在不同仓库间双向同步与安全还原，均可通过简单的命令一键完成。

---

## 核心命令总览速查

| 命令行指令 | 核心功能定位 | 典型使用时机 | 磁盘写入行为 |
| :--- | :--- | :--- | :--- |
| `pnpm content:sync` | 单次全量同步 | 每次开始本地预览前拉取内容 | 覆盖代码仓临时内容 |
| `pnpm content:watch` | 实时增量监听 | 在外部编辑器边写边看实时预览 | 自动增量写入 |
| `pnpm content:validate` | 内存安全预检 | 改完 YAML 快速排查语法与类型错误 | 纯内存校验，零写盘 |
| `pnpm content:status` | 状态与差异检查 | 查看当前同步源路径与文件差异 | 只读检查 |
| `pnpm content:export` | 差异反向导出 | 将本地修改过的配置最小化导出到内容仓 | 写入内容仓 |
| `pnpm content:clean` | 安全重置与清理 | 清理代码仓临时副本并恢复初始演示状态 | 还原代码仓，自动备份快照 |
| `pnpm content:eject` | 一键解耦迁移向导 | 将单仓模式抽离为独立的私有内容仓 | 导出完整内容结构 |

> 提示：在 Windows PowerShell 终端中，建议使用 `pnpm.cmd <命令>` 执行。

---

## 1. 实时增量监听：`content:watch`

```bash
pnpm content:watch
```

### 典型适用场景
你在 Obsidian、VS Code 或 Typora 等外部编辑器中撰写文章或调整 YAML 配置，希望在保存文件时，本地浏览器能自动刷新并呈现最新效果。

### 执行的核心动作与规则
- **增量响应**：内部采用防抖监听机制，只同步发生变化的文件；
- **配置即时编译**：修改任何 `config/*.yaml` 时，自动重新生成 TypeScript 配置桥接文件并触发 Astro 热重载；
- **媒体资源联动**：在外部新增图片或相册时，自动同步至代码仓对应目录。

### 安全保护与注意事项
- 退出监听只需在终端按下 `Ctrl + C`；
- 需配合另一个终端窗口中运行的 `pnpm dev` 共同使用。

## 2. 内存安全预检：`content:validate`

```bash
pnpm content:validate
```

### 典型适用场景
刚修改完某个 `config/*.yaml` 配置文件或文章的 Frontmatter，不想启动耗时的本地预览服务器，也不想真正修改磁盘文件，只想快速确认字段拼写与格式是否正确。

### 执行的核心动作与规则
- **纯内存校验**：在内存中完成 YAML 解析、模式比对与 TypeScript 类型诊断；
- **零磁盘写入**：不会向代码仓或内容仓写入任何临时文件；
- **精准错误提示**：若字段拼写错误（如将 `title` 误写为 `titel`），终端会高亮输出行号与正确的推荐字段。

### 安全保护与注意事项
- 适合作为 Git 提交前或持续集成流水线中的第一道质量卡口；
- 如果预检报错，修正错误后再次运行直至显示绿色的校验通过提示。

## 3. 状态与差异检查：`content:status`

```bash
pnpm content:status
```

### 典型适用场景
长时间未操作或切换了分支，想确认当前本地绑定的是哪个内容仓库、远程连接是否通畅、是否有未同步的文件或配置覆盖项。

### 执行的核心动作与规则
- 输出当前生效的 `CONTENT_DIR` 或 `CONTENT_REPO_URL`；
- 输出当前已覆盖的配置文件清单与纯内容文章总数；
- 检查是否存在未捕获的路径或格式异常。

---

## 4. 差异反向导出：`content:export`

```bash
pnpm content:export
```

### 典型适用场景
在主题代码仓的本地开发环境中临时调试了某些配置或样式，希望将这些修改反向沉淀回外部的内容仓库。

### 执行的核心动作与规则
- **最小化覆盖导出**：只导出相对于主题默认配置发生过修改的键值，绝不将主题的默认值硬编码写死在 YAML 中；
- **保护未来升级**：由于未修改的项不会被导出，日后主题新增特性时，内容仓能继续平滑继承最新默认值。

### 安全保护与注意事项
- 导出前会自动提示将要写入的文件清单；
- 确认后会覆盖内容仓中的对应文件，建议内容仓在 Git 干净状态下执行。

---

## 5. 安全清理与重置：`content:clean`

```bash
pnpm content:clean
```

### 典型适用场景
想将主题代码仓恢复到干净的纯初始演示状态，或者排除因本地临时测试产生的残留脏数据。

### 执行的核心动作与规则
- **自动快照备份**：在清理任何数据之前，系统会自动将当前的本地内容打包归档到 `.cache/content-backups/` 目录下，并以时间戳命名；
- **重置代码仓**：安全清除代码仓内同步的内容副本，并将内置演示文章与默认配置恢复就位。

### 安全保护与注意事项
- **你的真实内容在内容仓中完好无损**：此命令仅清理代码仓本地的临时副本；
- **快照随时可查**：如果不小心误清理了本地临时修改，可以在 `.cache/content-backups/` 中找到完整的压缩包快照进行找回。

---

## 6. 一键解耦迁移：`content:eject`

```bash
pnpm content:eject --target <目标目录路径>
```

### 典型适用场景
原先以单仓库模式运行博客的用户，希望一键将现有的文章、相册、自定义页面数据和配置文件抽离出来，初始化为一个崭新、独立的双仓内容仓库（通常只需执行一次）。

### 执行的核心动作与规则
- 自动提取全部文章、动态、相册、数据实体与配置覆盖项；
- 自动生成符合规范的 `shirone.content.json` 清单文件与 GitHub Actions 自动化触发工作流；
- 保持原始文件目录结构与元数据完整。
