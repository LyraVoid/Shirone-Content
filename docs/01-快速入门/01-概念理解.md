# 什么是内容分离架构

## 用通俗的比喻理解

如果把你的个人博客比作一栋精美的房子：

- **主题代码仓库**就是房子的**建筑框架、水电管道与装修工队**：它决定了按钮点起来滑不滑顺、深浅模式怎么切换、手机端菜单怎么弹出、图片怎么压缩变快。它由主题开发者维护，代码公开开源。
- **个人内容仓库**就是你入住后摆放的**家具日记、相框照片与生活便签**：里面放着你的所有原创文章、生活动态、相册、个人简介以及个性化颜色选择。它完全由你自己拥有，可以设为私有仓库。

在传统的博客建站模式中，房子和家具是死死焊死在一起的。一旦你想换个新墙面或者升级水电，一不小心就会把自己的日记和照片弄丢或产生代码冲突。

Shirone 的**内容分离架构**把两者彻底解耦：你的内容永远只留在你自己的私有内容仓库中，主题代码仓库只负责纯粹的构建与展示。

---

## 为什么一定要进行内容分离

### 1. 享受上游升级零冲突

开源主题会不断推出新功能、修复漏洞并优化排版。
在内容分离模式下，你的所有文章和配置都不在代码仓里。当主题发布新版本时，你在代码仓直接执行一键拉取合并，**绝不会发生任何文章代码冲突**。

### 2. 严密保护个人隐私

你可能希望将主题代码仓库公开在 GitHub 上展示给他人，但博客文章中往往包含：
- 未完成的草稿与生活随笔；
- 个人家庭相册或私密日记；
- 站点的专属凭证配置。

通过内容分离，你可以将**内容仓库设为私有**，将**代码仓库设为公开**。外界只能看到主题程序，无法访问你的私有文章与媒体源文件。

### 3. 专注内容创作，告别打包报错

创作者无需深入研究复杂的编译工具链与依赖包。你只需关注两个最简单的事情：
- 在 `content/` 目录下用 Markdown 写文章；
- 在 `config/` 目录下用清晰的 YAML 文件调整网站标题或颜色。

---

## 双仓协同的工作流程

整个流程完全自动化，不需要你手动搬运文件：

1. **你在内容仓库中创作**：写完文章后，执行 `git push` 推送到 GitHub；
2. **自动化流水线启动**：内容仓库中的工作流自动通知代码仓库；
3. **安全物化与深合并**：代码仓库自动拉取你的最新文章，并将你的配置与主题默认配置进行精准合并；
4. **编译与全网分发**：代码仓库生成高速静态网页，并自动部署上线。
